## Automatically request credit

Pass optional `automatically_request_credit: true` when actioning an alert with a **credit-eligible** reason code to request and auto-approve a credit in the same call:

| Eligible reason codes | Notes |
| --- | --- |
| `AlreadyRefunded` | Resolved code; eligible for credit |
| `AlreadyChargeback` | Decline code; eligible for credit |
| `MIDLost` | Decline code; eligible for credit |
| `ResolvedCancelled` | Decline code; eligible for credit |

Credit is **only** granted when all of the following are true:

- The reason code is one of the eligible codes above
- The merchant is **not** billed for resolved alerts
- The alert is not RDR
- The alert is at most 7 days old
- The alert does not already have a credit request

If a credit will not be granted, **no** credit request is opened — the alert is still updated normally and the response body does not include credit fields.

When a credit **is** granted, the `200` response includes:

```json
{
  "credit_granted": true,
  "credit_request_id": "al_..."
}
```

See [Reason Codes](/reference/reason-codes) for the full list of codes and credit eligibility.
