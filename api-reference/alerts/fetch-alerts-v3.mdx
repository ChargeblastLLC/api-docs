## Filtering

Filters are bracketed query parameters and combine with AND:

```
GET /api/v3/alerts?filter[type]=TC40&page=1&per=100
GET /api/v3/alerts?filter[type]=RDR,CDRN&filter[isMatched]=false
GET /api/v3/alerts?filter[startDate]=2026-06-01&filter[endDate]=2026-06-30
```

Values are case-insensitive, and a value that is not recognised returns a `400` naming the accepted values rather than being ignored.

<Warning>
API keys are scoped to a single company. If your organisation has several companies in Chargeblast, repeat the request once per company key to export all of your alerts.
</Warning>

## Matched and unmatched alerts

Chargeblast matches each incoming alert against the transactions it has synced from your processors. `isMatched` tells you whether that succeeded, and it is the rule behind why some alerts carry transaction-level detail and others do not.

When `isMatched` is `false`, these fields are `null` (and `isRefunded` is `false`): `externalOrder`, `externalUrl`, `customerId`, `customerEmail`, `metadata`, `attributes`, `mid`, `processor`. The alert's own fields, supplied by the card network, are always present: `card`, `amount`, `currency`, `arn`, `authCode`, `bin`, `caid`, `networkId`, `issuer`, `descriptor`, `subprovider`, `reasonCode`.

Use `filter[isMatched]` to retrieve one group at a time.

<Info>
Each alert may include optional **`attributes`**: a dictionary of string keys and string values (for example `order_number`, `processor_id`). The same field appears on [webhook](/api-reference/webhooks/setup#body) payloads when present.
</Info>

## Pagination

`page` is 1-based and defaults to `1`; `per` defaults to `10`. Read `total` from the response to know how many pages to walk.
