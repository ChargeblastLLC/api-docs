<Info>
The `subprovider` field indicates the alert network. See [Alert Types](/reference/alert-types) for all possible values and descriptions.
</Info>

<Info>
Each alert may include optional **`attributes`**: a dictionary of string keys and string values (for example `order_number`, `processor_id`). The same field appears on [webhook](/api-reference/webhooks/setup#body) payloads when present.
</Info>

<Tabs>
  <Tab title="v3 (current)">
    ```http
    GET https://api.chargeblast.com/api/v3/alerts
    ```

    Get all the alerts from your Chargeblast account, filtered by network, status, match state, or date range. Each company has its own API key, so run the export once per key.

    ### Filtering

    Filters are bracketed query parameters and combine with AND:

    ```
    GET /api/v3/alerts?filter[type]=TC40&page=1&per=100
    GET /api/v3/alerts?filter[type]=RDR,CDRN&filter[isMatched]=false
    GET /api/v3/alerts?filter[startDate]=2026-06-01&filter[endDate]=2026-06-30
    ```

    Values are case-insensitive, and a value that is not recognised returns a `400` naming the accepted values rather than being ignored.

    <Note>
    The same clauses can alternatively be sent as a JSON body with a top-level `filter` object, as a fallback for clients that prefer a body over a query string:

    ```json
    { "filter": { "type": "RDR,CDRN", "isMatched": false, "startDate": "2026-06-01" } }
    ```

    Query-string filters take precedence — the body is only read when the query carries no `filter[...]` clause. Pagination (`page` / `per`) is always read from the query string, never the body. Prefer the query-parameter form above; the body fallback exists mainly for backwards compatibility.
    </Note>

    ### Matched and unmatched alerts

    Chargeblast matches each incoming alert against the transactions it has synced from your processors. `isMatched` tells you whether that succeeded, and it is the rule behind why some alerts carry transaction-level detail and others do not.

    When `isMatched` is `false`, these fields are `null` (and `isRefunded` is `false`): `externalOrder`, `externalUrl`, `customerId`, `customerEmail`, `metadata`, `attributes`, `mid`, `processor`. The alert's own fields, supplied by the card network, are always present: `card`, `amount`, `currency`, `arn`, `authCode`, `bin`, `caid`, `networkId`, `issuer`, `descriptor`, `subprovider`, `reasonCode`.

    Use `filter[isMatched]` to retrieve one group at a time.

    <Warning>
    API keys are scoped to a single company. If your organisation has several companies in Chargeblast, repeat the request once per company key to export all of your alerts.
    </Warning>

    ### Headers

    <ParamField header="X-API-Key" type="string" required>
      Your API key. Sent in the `X-API-Key` header.
    </ParamField>

    ### Query parameters

    <ParamField query="filter[type]" type="string">
      Alert networks to include, comma-separated. Possible values: `Ethoca`, `CDRN`, `RDR`, `Discover`, `AMEX`, `JCB`, `Cancel`, `TC40`, `SAFE`, `PayPal`. Case-insensitive. An unrecognised value is rejected with a `400`.
    </ParamField>

    <ParamField query="filter[status]" type="string">
      Alert reason codes to include, comma-separated. Possible values: `Resolved`, `ResolvedPartial`, `ResolvedCancelled`, `AccountCancelled`, `CancellationProcessed`, `UnmatchedGeneral`, `UnmatchedCannotFindTransaction`, `Duplicate`, `MIDLost`, `AlreadyRefunded`, `AlreadyChargeback`, `Ineligible`, `TDS`, `CannotCancel`, `MatchedWillShip`, `EscalateChargeback`, `ContactedShipper`, `WIP`, `Error`, `None`, `NotMyDescriptor`, `Unactioned`, `TIMEOUT`. Case-insensitive. An unrecognised value is rejected with a `400`.
    </ParamField>

    <ParamField query="filter[isMatched]" type="boolean">
      `true` returns only alerts matched to a transaction, `false` only unmatched ones.
    </ParamField>

    <ParamField query="filter[startDate]" type="string">
      Only return alerts created on or after this point. ISO 8601 date/time (`2026-06-01T00:00:00Z`) or a date (`2026-06-01`).
    </ParamField>

    <ParamField query="filter[endDate]" type="string">
      Only return alerts created on or before this point. ISO 8601 date/time or a date.
    </ParamField>

    <ParamField query="page" type="integer" default="1">
      The page to request. 1-based; defaults to `1`.
    </ParamField>

    <ParamField query="per" type="integer" default="10">
      How many objects to request per page. Defaults to `10`. Read `total` from the response to know how many pages to walk.
    </ParamField>
